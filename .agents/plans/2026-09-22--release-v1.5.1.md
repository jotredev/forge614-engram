# Publicación v1.5.1 — Plan de release

**Objetivo:** Preparar `v1.5.1` con la corrección de `startup-context` y una raíz de almacenamiento explícita y segura mediante `FORGE614_HOME`; la publicación permanece suspendida hasta revisión humana.

## Scope

- Centralizar la raíz de Engram: `FORGE614_HOME` absoluta cuando está definida; de lo contrario, la ruta histórica `~/.forge614` sin cambio.
- Derivar desde esa raíz la configuración `.env`, SQLite, binario, actualización, desinstalación y las rutas de instalación que les correspondan.
- Rechazar `FORGE614_HOME` vacía o relativa como `INVALID_FORGE614_HOME`, sin crear ni consultar la raíz histórica.
- Añadir pruebas unitarias, de integración CLI y de instaladores; actualizar documentación ES/EN de instalación y límites, changelog y huellas locales.
- No crear commit, tag, push ni publicación.

## Decisions

1. **Versión:** `1.5.1` es un parche: restablece un contrato documentado de `format: 1`, sin añadir campos ni cambiar su semántica.
2. **Fuente de verdad:** los cuatro documentos locales 03/10 ya corregidos son el contenido revisado para las páginas Notion existentes identificadas en `docs/notion-map.json`; se actualizan, no se duplican.
3. **Secuencia de publicación:** actualizar versión y metadatos locales; verificar suite, tipo y binario; actualizar Notion; confirmar las páginas; crear commit de release y tag `v1.5.1`; empujar el tag para activar el workflow de release; vigilar el workflow y confirmar los assets publicados.
4. **Seguridad:** la publicación no incluye bases SQLite, perfiles personales ni datos de pruebas. Notion recibe únicamente las cuatro páginas públicas ya revisadas. Los cambios remotos finales requieren confirmación inmediata en la UI.
5. **Ayuda de CLI:** la ayuda general debe distinguir la resolución de lectura de la vinculación: `startup-context` acepta cualquier directorio existente y legible; la vinculación sigue requiriendo una identidad de proyecto apta para vínculo. Esto evita publicar un contrato visible contradictorio.
6. **Raíz única:** `forge614Home()` será la única autoridad de rutas de producción. Lee `FORGE614_HOME` en cada invocación para que la CLI y las pruebas no queden fijadas al entorno de carga; una variable presente pero vacía, relativa o insegura falla con `INVALID_FORGE614_HOME` antes de abrir o crear archivos.
7. **Compatibilidad:** sin `FORGE614_HOME`, los valores derivados deben conservar exactamente `homedir()/.forge614`; las inyecciones de ruta en pruebas permanecen explícitas y no alteran la ruta de producción.
8. **Instalación y ciclo de vida:** el instalador, el instalador desde fuente, la actualización, la desinstalación y el mantenimiento de PATH usarán la misma raíz efectiva. El instalador rechaza una variable inválida antes de crear destino; el error JSON de contrato aplica a la CLI.
9. **Impacto en el procedimiento de agentes:** **Sí.** Todo asistente o host que configure `FORGE614_HOME` debe revalidar que pasa una ruta absoluta y que su `startup-context` observa el almacén aislado correcto; quien no la configure mantiene la ruta histórica.
10. **Autorización de publicación:** el usuario autorizó explícitamente publicar `v1.5.1` aun con 01/08 marcados como `notionSyncPending: true`. Ese marcador conserva visible la deuda de sincronización remota y no altera el artefacto ni sus contratos.

**Sí.** Un asistente o host que configure `FORGE614_HOME` debe comprobar que el valor sea una ruta absoluta y volver a validar que `startup-context` consulta esa raíz. Quien no configure la variable conserva la ruta histórica byte por byte y no requiere ajuste.

## Result

Implementado y pendiente de revisión humana. `src/infrastructure/filesystem/paths.ts` concentra `forge614Home()`: una variable `FORGE614_HOME` presente debe ser absoluta y no vacía; de lo contrario produce `INVALID_FORGE614_HOME`. Sin variable conserva exactamente `homedir()/.forge614`. De esa raíz derivan `.env`, SQLite, binario, actualización, desinstalación, limpieza de PATH e instaladores. Los snapshots no tienen una raíz independiente: operan sobre la base SQLite derivada.

Pruebas añadidas: rutas unitarias (default/absoluta/inválida), aislamiento CLI `init`/`save`/`startup-context`, valores inválidos de CLI, actualizador, desinstalación, publicación de PATH y ambos instaladores. La suite se ejecutó en dos particiones disjuntas de sus 73 archivos para obtener estado terminal dentro del límite de ejecución: 207 correctas, 1 omitida, 0 fallas; y 238 correctas, 9 omitidas, 0 fallas. `bun run typecheck`, `git diff --check`, `bash -n scripts/install.sh scripts/install-from-source.sh` y la compilación standalone `1.5.1` pasaron.

Salida real de CLI compilada con `FORGE614_HOME` temporal:

```text

home        {"format":1,"status":"unbound","sharedHasColor":true}
```

La documentación local ES/EN 01 y 08 y `CHANGELOG.md` describen la raíz alternativa, el fallo seguro y las dos entradas de `1.5.1`. Por corrección explícita del usuario, las cuatro entradas 01/08 ES/EN de `docs/notion-map.json` ahora contienen las huellas SHA-256 locales reales, `reviewedProductVersion: "1.5.1"` y `notionSyncPending: true`; ese campo declara que el espejo remoto aún requiere sincronización. El usuario autorizó continuar con commit, tag, push y publicación. Se creó el commit de release; el tag y la ejecución remota son la fase restante.
